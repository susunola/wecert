# 两轮真实端到端验证（2026-09-24）

> 范围：真实 Let's Encrypt **staging**、真实 Cloudflare DNS API、真实腾讯云 SSL/CLB、真实 Amazon S3 与腾讯 COS。
> 不使用 Let's Encrypt production，不应将本记录理解为生产 CA 配额或自然到期续期的验证。

## 结果

两轮使用独立子域名、独立 SQLite 状态库和独立远端备份前缀，均完成以下链路：

1. 创建 ACME 账号和 staging DNS-01 订单。
2. 经 Cloudflare 写入挑战 TXT，验证后清理。
3. 用 `VACUUM INTO` 创建状态快照并上传到 S3 与 COS。
4. 签发并上传证书到腾讯云 SSL。
5. 用 `UpdateCertificateInstance` 将同一个测试 HTTPS listener 依次从旧证书换到第 1 轮证书、再换到第 2 轮证书。
6. 用 `wecert-clbverify` 从腾讯云控制面读回 listener 的实际绑定。
7. 分别从 S3 和 COS 下载最新快照并恢复到隔离状态库。

| 轮次 | 上传的腾讯云证书 | CLB 读回绑定 | S3 恢复 | COS 恢复 |
|---|---|---|---|---|
| 1 | `b2kL7n8s` | `b2kL7n8s` | 通过 | 通过 |
| 2 | `b2kf8kYG` | `b2kf8kYG` | 通过 | 通过 |

测试 listener 为独立 HTTPS:443 listener；原有 HTTP listener 未修改。

## 本次暴露并修复的兼容性

- COS 的批量删除要求 `Content-MD5`。远端保留策略对 COS 改为逐对象删除，S3 仍使用批量删除。
- 某些网络出口拒绝 UDP/53、允许 TCP/53；DNS 查询在 UDP `REFUSED` 时会回退 TCP。
- lego 的 Cloudflare provider 需要系统递归 DNS 来完成自身的 UDP zone lookup，而 wecert 的传播判断可使用单独配置的递归 DNS。两条路径已拆分，避免受限出口让 TXT 写入或验证永久失败。
- Cloudflare provider 在进程重启后遗失内部 record ID 时，wecert 会按精确 FQDN 与 TXT 值恢复清理，不会删除同名的其他挑战值。
