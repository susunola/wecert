WECERT / PRODUCTION READINESS · 2026-09-27

生产前测试场景矩阵

围绕当前已实现能力设计的可执行测试集。目标不是继续扩展功能，而是证明签发、部署、备份、恢复、策略、权限和故障保护在真实环境中可重复、可观测、可回滚。

适用版本：main 当前代码；CA 默认使用 Let’s Encrypt Staging。生产 CA 只允许通过小范围 canary 场景验证。
执行原则：每个场景必须保存命令、配置摘要、日志片段、指标快照和外部证据（DNS、CLB、对象存储或 SFTP）。破坏性恢复、撤销、删除远端备份和生产 CA 操作需要人工确认。

测试分层

Tier 0 · 每次提交

单元、竞态、配置拒绝、模拟 CA/DNS/存储故障。目标是分钟级反馈。

Tier 1 · 每日 staging

真实 DNS-01、S3/COS/SFTP、加密快照、backup-drill、恢复和幂等性。

Tier 2 · 发布前 canary

一台守护进程、一个非关键域名、一个 CLB 监听；验证公网 TLS、回滚和告警。

场景清单

ID / 层级优先级能力与场景前置条件执行步骤预期结果 / 证据
CFG-001
T0		P0配置安全拒绝缺少 statePath；远端目标未配置密钥；文件权限 0644。wecert -dry-run 分别执行。非零退出；指出具体字段和修复建议；不创建空状态库。
ACME-001
T1		P0单域名 DNS-01 首次签发Staging CA、Cloudflare/DNSPod 权限、无现存证书。执行 -once；观察 TXT 创建、传播、清理。订单 valid；证书 SAN 正确；TXT 清理；state.db 与快照产生。
ACME-002
T1		P0通配符 + apex 共享 TXT同一证书包含 example.com 与 *.example.com。签发并在传播窗口内反复查询权威 NS。两个授权成功；同名 TXT 不互相覆盖；结束后无残留 TXT。
ACME-003
T1		P1幂等重跑与无变化收敛已有 valid 证书和 desired state。连续执行两次 -once。第二次不重复下单、不重复上传；日志说明 no-op；指标无异常增长。
ACME-004
T1		P1SAN 漂移已有域名列表；修改配置增加/删除一个 SAN。运行 reconcile，检查旧证书、订单与新证书。只为新声明收敛；旧证书保留到安全替换；最终 SAN 与声明一致。
ACME-005
T1		P1主 CA 限流切备用 CA配置已验证的 fallbackDirectories；模拟主 CA 429/503。注入主 CA 错误后执行一次 reconcile。只在允许的传输/服务/账户配额错误时切换；DNS/域策略错误不切换；日志记录 CA。
ACME-006
T2		P0生产 CA canary非关键域名、明确人工确认、可回滚窗口。切生产目录，仅签发一个域名；验证证书链和撤销预案。公网信任链正确；无重复订单；保存 order URL、证书指纹和撤销决定。
CLB-001
T1		P0CLB 上传与一次绑定HTTPS listener、证书未绑定。执行部署；控制台完成首次绑定；再次 reconcile。上传成功；后续由 wecert 识别绑定并完成更新；其他证书不受影响。
CLB-002
T1		P0SNI 与后端路由同监听两个域名、两个后端响应标识。分别用 SNI 发起 openssl s_client 与 curl。证书 SAN、证书指纹、HTTP 后端均与 Host/SNI 匹配。
CLB-003
T1		P1部署失败保护模拟 SSL API 超时或权限拒绝。执行签发/部署；恢复权限后重试。不覆盖最后已知可用证书；状态可重试；告警含资源和错误分类。
BKP-001
T1		P0加密快照 + 本地另一磁盘stateEncryption.keyFile；localDirs 指向独立挂载点。运行一次 pass，删除主库副本，使用备份恢复。快照可解密、SQLite integrity_check 通过；权限 0600；恢复后 dry-run 通过。
BKP-002
T1		P0S3/COS 真实上传、回读和 drill真实 bucket、最小权限凭据、版本/生命周期策略。上传后立即回读；执行 -backup-drill remote:target。大小与内容校验一致；HMAC/加密校验通过；不改变 live state。
BKP-003
T1		P0SFTP chroot 真实恢复外部 SFTP、known_hosts、专用密钥和目录。上传快照、删除本地副本、下载恢复、启动 dry-run。仅能访问 chroot 目录；快照和 HMAC sidecar 存在；恢复告警包含 rate-limit caveat。
BKP-004
T1		P1远端目标故障与重试阻断 S3/SFTP 网络或撤销写权限。运行 pass；恢复网络/权限后再运行。本地签发流程不被远端备份拖垮；失败有明确指标；恢复后自动补传且不产生重复损坏对象。
REST-001
T1		P0错误快照拒绝恢复截断 DB、篡改 HMAC、错误密钥各准备一份。分别执行 restore。全部拒绝；原 state.db 不被覆盖；错误说明完整性/密钥问题。
POL-001
T1		P1按域名 profile 与续签窗口两个证书使用不同 profile、renewBefore、deploy target。运行 onboarding/reconcile，检查生成声明与日志。策略只作用于匹配证书；profile、窗口和目标不串线。
POL-002
T1		P1失败降级与关键证书保护一个证书启用 failureFallback，一个显式禁用。模拟 subset issuance 或部署失败。允许降级的证书按策略继续；保护证书保持失败且不静默替换。
OPS-001
T1		P0SIGHUP 配置热加载daemon 运行中；先准备合法变更和非法变更。修改 DNS/备份/通知策略，发送 SIGHUP；再加载坏配置。合法配置原子切换且不中断当前 issuance；坏配置被拒绝，旧 runtime 保持运行。
OPS-002
T1		P1并发信号与重启恢复在 DNS propagation 或部署中发送 SIGHUP/SIGTERM。观察进程退出、再次启动和 state lock。不产生重复订单；WAL/锁清理正确；恢复后继续原订单状态机。
OBS-001
T0		P0指标、ready、告警一致性启动 metrics；注入即将过期、部署不一致、备份失败状态。抓取 /metrics，执行 prometheus rule 单测。指标标签稳定；告警触发和恢复；不泄露私钥、token、完整域名凭据。
WEB-001
T1		P1只读管理面与受保护恢复启用 web console；准备确认 token。查看证书、部署、限额、备份健康；无 token 调 restore；再用一次性确认执行。GET 只读；未确认的恢复/诊断不改变状态；确认 token 一次性、过期后失效。
SEC-001
T1		P1凭据治理与最小权限使用 env/file/CVM role 三种凭据来源。轮换 token；撤销旧 token；检查日志、备份和进程环境。旧凭据立即失效；secret 不进入日志/快照；CAM 权限仅覆盖 DNS、SSL、CLB 必要动作。
PERF-001
T2		P2多证书并发收敛10–25 个证书声明；Staging CA 和受控 DNS。并发运行 reconcile，记录 order、DNS API、SQLite 锁和总耗时。无状态损坏、无重复 TXT 冲突；限流退避生效；耗时和 API 调用量在预算内。
LIFE-001
T2		P2生命周期验收闭环可控测试域名和 staging 证书。签发 → ARI 窗口 → renewBefore fallback → 部署 → 旧证书归档 → revoke 预案。每个状态有可追踪事件；撤销不被误认为恢复；文档与实际命令一致。
E2E-001
T1		P0声明 → 签发 → CLB → 公网 TLS 全链路新域名、Cloudflare/DNSPod、Tencent SSL/CLB、可访问后端。生成声明；执行 -dry-run；运行 -once；完成首次 CLB 绑定；用独立网络执行 SNI 握手和 HTTP 请求。配置中的域名、ACME SAN、CLB 证书 SAN、公网证书指纹和后端 Host 路由完全一致。
E2E-002
T1		P0签发成功但部署失败 → 自动重试 → 最终收敛首次部署注入 SSL/CLB 权限拒绝；随后恢复权限。运行第一轮并记录旧证书；恢复 CAM 权限后再次运行；执行独立 CLB verify。第一次不破坏旧证书且状态保留待部署；第二次只执行必要动作；公网最终切换到新证书。
E2E-003
T1		P0DNS 传播超时 → 清理 → 重试闭环临时降低递归 DNS 可达性或使用隔离解析器。触发超时；检查 TXT 是否被清理；恢复解析后重试同一声明。失败订单不留下 TXT；state 中错误可分类；重试不会创建重复本地订单或泄漏 token。
E2E-004
T1		P1续签窗口 → 备份 → 部署 → 旧证书淘汰将测试证书置于 ARI/renewBefore 窗口；启用至少两个备份目标。运行 daemon/timer；观察续签、快照、S3/COS/SFTP 上传和 CLB 探测。新证书先持久化和备份再部署；公网探测通过后旧 material 才进入保留/清理路径。
E2E-005
T1		P1主备存储目标不一致 → 恢复优先级本地磁盘、S3、SFTP 三个目标；人为让其中一个上传失败。执行 pass；分别从成功目标执行 backup-drill；再恢复目标可用性。单个目标失败不会误报整体健康；健康目标可恢复；恢复后缺口可补齐且 retention 正确。
E2E-006
T1		P1运行中密钥轮换 → 热加载 → 下一轮备份daemon 运行；新旧 state/HMAC/云凭据均准备好。轮换凭据文件；发送 SIGHUP；验证旧凭据拒绝、新凭据成功；执行 drill 和 restore。当前 issuance 不被中断；新快照使用新凭据；旧凭据不出现在日志和新快照中。
E2E-007
T1		P0进程崩溃恢复 → 未完成订单继续在 order pending、TXT 已创建、部署中三个时间点终止进程。重启 daemon，重复执行 reconcile；检查 order URL、TXT、state lock 和最终公网证书。不重复注册账户/无谓下单；遗留 TXT 按生命周期清理；最终订单和部署收敛。
E2E-008
T1		P0恢复旧快照 → rate-limit caveat → 安全续签准备包含旧 order ledger 的快照；当前状态比快照更新。确认恢复；启动并观察 caveat；在窗口内触发一次续签。启动明确提示 ledger 落后；CA 拒绝时退避而非丢证书；窗口结束后计数恢复准确。
E2E-009
T2		P1批量证书分批收敛与限流10–25 个不同 profile/部署目标的域名。一次加载全部声明；制造 CA 429；观察退避、并发度和已成功证书的部署。成功批次不回滚；失败批次可重试；限流指标和告警按证书维度可定位。
E2E-010
T2		P1只读诊断 → 受保护恢复 → 公网复核Web 管理面启用；准备损坏/过期状态和可用快照。先查看证书/部署/限额/备份健康；触发只读诊断；经一次性确认恢复；最后执行 CLB verify 和 TLS 探测。诊断不改变状态；未确认恢复被拒绝；恢复后控制面、state、CLB 和公网证据相互一致。

发布门槛

必须全部通过

  • CFG-001、ACME-001/002、CLB-001/002
  • BKP-001/002/003、REST-001
  • OPS-001、WEB-001、SEC-001

允许带风险发布

  • 主 CA fallback 已完成 staging 演练
  • 生产 canary 仅一个非关键域名
  • 性能与生命周期测试有基线和回滚方案

每次保留证据

  • 配置 commit、版本、命令和 UTC 时间
  • 日志、指标、证书指纹、DNS/CLB/S3/SFTP 证据
  • 失败场景的恢复动作和残留资源清单
